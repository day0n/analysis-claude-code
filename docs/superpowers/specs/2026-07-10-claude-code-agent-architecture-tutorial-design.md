# Claude Code Agent 架构教程重塑设计

## 目标

把当前的架构速览重塑为一份可系统学习的 Agent 架构教程。读者学完后应能够：

1. 建立 Claude Code 从启动到结束的完整运行时模型；
2. 说清一个 Agent 由哪些部分构成，这些部分在 API 请求中的位置；
3. 理解主查询循环、工具回合、上下文压缩和错误恢复的状态转换；
4. 理解 Tools、Skills、MCP、Hooks、Memory、Sandbox 和 Subagent 之间的边界；
5. 识别可迁移到其他 Agent 系统的架构设计。

## 读者与表达边界

- 同时面向 Claude Code 使用者和 Agent 架构学习者。
- 全文使用中文；英文只保留源码中的正式概念名和 API 字段名。
- 只讲架构、协议、生命周期、状态和边界，不展开函数、类、分支逻辑或 TypeScript 实现。
- JSON 仅用于展示最终 API 协议；Mermaid 仅用于展示层次、时序和状态转换。
- 保持紧凑，但不以省略关键架构为代价。

## 教学主线

教程使用两条连续主线，而不是按源码目录组织：

1. **构造主线**：身份、系统 Prompt、用户与项目上下文、工具能力图、模型配置、权限和运行时状态如何组成 Agent。
2. **运行主线**：用户输入如何经过上下文编译、API 请求、流式输出、工具执行、结果回填、压缩和恢复，直到任务结束。

安全、扩展、记忆和多代理章节必须回到这两条主线，不做孤立的功能清单。

## 每章的固定分析框架

每章根据主题使用下列框架，但不为了形式机械重复标题：

- **解决的问题**：为什么需要这一层。
- **架构位置**：它属于控制面、模型面、执行面还是持久化面。
- **输入与输出**：与相邻模块交换什么。
- **生命周期**：在启动、回合、工具执行、压缩或结束的哪个时刻发生。
- **精妙设计**：说明该设计避免了什么问题，又付出了什么代价。
- **边界和误解**：明确它不负责什么，以及“源码存在”与“当前必定启用”的区别。

## 必须讲透的设计

- Agent 不是一个单一 Prompt，而是“身份 + 上下文 + 能力 + 策略 + 状态”的运行时实例。
- 稳定系统 Prompt 与动态附件分离，同时服务于时序正确性和 Prompt 缓存。
- `<system-reminder>` 是内部协议标签，不是 Messages API 的第二套 system 角色。
- 工具可见性、参数权限、操作系统沙盒和 Worktree 是四层独立边界。
- ToolSearch 把工具集从“全部常驻”改为“名称常驻、结构按需”。
- 工具调用与工具结果通过标识严格配对，工具结果作为新的 `user` 内容推进状态机。
- 上下文管理分为工具结果清理、微压缩、完整压缩和压缩后重建，而不是只有一次总结。
- 错误恢复必须区分可重试传输错误、上下文过长、媒体过大、模型不可用、用户中断与 Hook 阻止。
- 普通 Subagent 只接收委派 Prompt，Fork 则复用主对话前缀；两者都不共用可变运行状态。
- 后台 Agent、Worktree 和 Agent Team 分别解决执行时间、文件冲突和协作协议问题，不是同一种隔离。
